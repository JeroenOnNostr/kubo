- **KUBO-194: Search waits for all relays (fix typeahead flicker) + restore sort term in initial query** (`236b1e23`)
  Bug report: profile-search typeahead showed matching names *while typing* but **intermittently dropped them when the word was completed** ("sometimes I show up, sometimes I disappear from the list"). Root cause: the pool's global `eoseTimeout: 300` ([NostrProvider.tsx](src/components/NostrProvider.tsx) — deliberate, keeps feeds fast) aborts a search query 300ms after the **first** of the two Ditto search relays (`relay.ditto.pub` + `relay.dreamith.to`, the 2nd added in `b25be7e8`) sends EOSE, and `NPool.query()` hardcodes that timeout with no per-call override. Whichever relay won the race decided the result — when the completed token only matched on the *slower* relay, that relay was aborted before replying, so the match vanished non-deterministically. The local-cache fallback in `useSearchProfiles` masked it only for already-loaded profiles (hence "sometimes"). Fix: new helper [searchQuery.ts](src/lib/searchQuery.ts) drives `nostr.req` directly with a **2500ms** `eoseTimeout` (`req` honours per-call overrides; `query` does not), waits for **all** search relays to EOSE, dedupes replaceable events keeping latest, and returns partial results without throwing (matches `query`'s contract so TanStack `useQuery` never errors). Applied to [useSearchProfiles.ts](src/hooks/useSearchProfiles.ts) (the dropdown — the user-visible bug), [useSearchEvents.ts](src/hooks/useSearchEvents.ts) (community/follow-pack search; empty-query firehose stays on fast `query`), and the [useStreamPosts.ts](src/hooks/useStreamPosts.ts) initial batch; feed/streaming paths keep the fast 300ms untouched. Widened `NostrBatcher.req`'s opts type to carry `eoseTimeout` (already forwarded at runtime). **Bonus fix (same file):** `sort:hot`/`sort:trending` was appended to the search string *after* the filter was built in `useStreamPosts`, so SearchPage post-sorting never reached the relay — reordered so it's included. **Tests:** [searchQuery.test.ts](src/lib/searchQuery.test.ts) (8 unit) + [searchQuery.race.test.ts](src/lib/searchQuery.race.test.ts) (real `NPool` two-relay sandwich: proves the 300ms path **drops** the slow match and the 2500ms path **keeps** it, stable over 12 runs).
