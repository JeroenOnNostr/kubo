- **KUBO-133: TEPP bugfix — reference-closure prefetch (kid feed went empty / kid couldn't reply)**
  Root cause: the vendored `evaluateEvent` reads referenced events (reply parent, quoted note, repost target) from a caller-supplied `eventCache` and returns `pending` for anything missing; the `prefetchReferenceClosure` its doc comment names was never implemented, so **every reply/quote/repost evaluated to `pending`** → dropped from the kid feed (read) and kid replies threw `TeppDeniedError` (write). This is what [ParentTrustDiagnosticsPage](src/pages/ParentTrustDiagnosticsPage.tsx) was built to chase. Fix: new [src/lib/tepp-adapters/referenceClosure.ts](src/lib/tepp-adapters/referenceClosure.ts) (`prefetchReferenceClosure`, BFS to depth 4, one batched id-query per hop) + new [src/hooks/useTeppReferenceCache.ts](src/hooks/useTeppReferenceCache.ts) (TanStack-Query hook keyed on `(fingerprint, sorted seed ids)`). Threaded into [useKuboTeppFeedFilter.ts](src/hooks/useKuboTeppFeedFilter.ts) (now takes the feed's events; 4 call sites in [Feed.tsx](src/components/Feed.tsx) pass them), [useKuboTeppEvaluateEvent.ts](src/hooks/useKuboTeppEvaluateEvent.ts), and [useKuboTeppGate.ts](src/hooks/useKuboTeppGate.ts) (gate is now async; `useNostrPublish` awaits it). **Fail-open policy:** hide/block only on concrete `deny`; `pending` (loading or unfetchable reference) shows/allows, and `pending` verdicts are not memoized.
